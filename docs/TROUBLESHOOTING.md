# Troubleshooting

Start here:

```bash
agent-handoff doctor
agent-handoff doctor --json
agent-handoff list
```

Useful files under `$AGENT_HANDOFF_HOME`:

```text
logs/integration.log
logs/upload.log
queue/*.json
state/sessions.json
state/index_upload.json
config/config.json
```

Never paste tokens or rclone configuration contents into chat or logs.

## Installation refuses invalid OpenCode or AGY JSON

The installer validates managed external JSON before changing any plugin, hook, or instruction file. If it reports `invalid opencode.json` or `invalid AGY hooks.json`, fix the JSON first:

```bash
python3 -m json.tool ~/.config/opencode/opencode.json
python3 -m json.tool ~/.gemini/config/hooks.json
```

A failed installation restores the managed integration files it had already changed. Existing `*.backup-agent-handoff-*` files remain available for inspection.

## Rollback refuses a legacy snapshot

A snapshot created before ownership manifests has no `manifest.json`. The rollback refuses it because newer managed files cannot be separated safely from unmanaged files. Install or upgrade once with the current version to create a snapshot with ownership information, then roll back to that snapshot. Runtime configuration and data are never modified by the refusal.

## Installer reports an unsafe managed path

The installer never follows source symlinks or writes through destination symlink components. If it reports an unsafe managed path, inspect the runtime paths involved and replace the symlink with a normal directory before retrying. Do not delete runtime data or configuration directories.

## Google Drive is not authorized

Symptoms:

- `doctor` reports `Google Drive access: rclone config not found` or `Not ready`.
- Queue items show `Google Drive unavailable`.
- `agent-handoff auth --check` exits nonzero.

Fix:

```bash
agent-handoff auth
setup/gdrive-auth.sh
```

Use the token import flow described by the command. The import verifies Drive before keeping the config. Then:

```bash
agent-handoff auth --check
agent-handoff doctor
agent-handoff retry-upload --force
```

## The remote exists but uploads fail with auth errors

Possible causes:

- Expired or revoked refresh token.
- Token generated by a different OAuth client or incompatible rclone version.
- The Google account cannot access the folders.
- A folder was moved or deleted.

Fix:

1. Re-run `rclone authorize "drive"` on a browser-capable machine.
2. Import the new token with `agent-handoff auth --import-token-file`.
3. Run `agent-handoff auth --check`.
4. Run `agent-handoff retry-upload --force`.

The import restores the previous rclone config if the new token cannot access Drive.

## Token import fails and the config is restored

That is intentional. Check:

- The token file is valid JSON.
- It contains `access_token` and/or `refresh_token`.
- The Google account can open the configured Drive root.
- The rclone versions on the browser machine and this host are compatible.
- The file contains only the JSON object, without surrounding prose.

## Drive folder ID check fails

`doctor` or `retry-upload` refuses to upload when a configured folder ID is not a direct child of the reports root.

```bash
agent-handoff project list --check
agent-handoff project add --name "Project" \
  --folder-id "<verified-folder-id>" --path /path/to/project
```

If duplicate folders with the same name exist, the system refuses to guess. Supply the exact folder ID.

## Queue is stuck

Inspect queue metadata without printing report contents:

```bash
python3 - <<'PY'
import glob, json, os
from pathlib import Path
root = os.environ.get("AGENT_HANDOFF_HOME", str(Path.home() / "agent-handoff"))
for path in sorted(glob.glob(root + "/queue/*.json")):
    data = json.load(open(path))
    print(data.get("id"), data.get("kind"), data.get("project"), data.get("run_id"),
          "attempts:", data.get("attempts"), "error:", data.get("last_error"),
          "next:", data.get("next_attempt_at"))
PY
```

Then:

```bash
agent-handoff retry-upload --force
agent-handoff retry-upload --force --project Project
```

Backoff is automatic. `--force` ignores the timer. Do not delete report directories; the queue can retry indefinitely.

## Upload verified but the file is not where expected

Check the remote path recorded in `COMPLETE.json`:

```bash
python3 - <<'PY'
import glob, json, os
from pathlib import Path
root = os.environ.get("AGENT_HANDOFF_HOME", str(Path.home() / "agent-handoff"))
for path in glob.glob(root + "/data/projects/*/TASKS/*/RUNS/*/COMPLETE.json"):
    data = json.load(open(path))
    print(data["task_id"], data["run_id"], data["upload"]["verified"], data["report"]["remote_path"])
PY
```

Verify with rclone manually (read-only):

```bash
rclone lsf "gdrive,root_folder_id=<PROJECT_FOLDER_ID>:TASKS/<TASK_FOLDER>/RUNS/<RUN_ID>/"
```

Do not use `rclone sync`.

## MD5 mismatch

Possible causes:

- Truncated or interrupted upload.
- rclone did not support MD5 for the object; read-back should be used automatically.
- A Drive conversion changed the object (not expected for `.md`/`.json`).

The run remains pending. Retry:

```bash
agent-handoff retry-upload --force --run <run-id>
```

## Index is missing or stale

```bash
agent-handoff index --project Project
agent-handoff index --project Project --upload
agent-handoff retry-upload --force
```

The uploaded index intentionally lists only upload-verified runs.

## OpenCode plugin did not create a report

```bash
agent-handoff doctor
ls -l ~/.config/opencode/plugin/agent-handoff.js
tail -50 "$AGENT_HANDOFF_HOME/logs/integration.log"
```

Reinstall:

```bash
python3 setup/install.py --home "$AGENT_HANDOFF_HOME"
```

Test with a small real session:

```bash
opencode run --dir /path/to/project -m <model> --title "Handoff plugin test" "Reply with exactly: PLUGIN_TEST_OK"
agent-handoff list --project Project
```

Notes:

- OpenCode must not be started with `--pure` if external plugins are expected.
- Subagent child sessions are skipped.
- A session with no assistant text is recorded as `blocked`, not `succeeded`.

## AGY hook did not create a report

Check the hook config:

```bash
python3 -m json.tool ~/.gemini/config/hooks.json
```

It should contain an `agent-handoff-report` entry whose command includes:

```text
agent-handoff hook agy
```

Test the hook manually:

```bash
printf '%s\n' '{"hookEventName":"Stop","conversationId":"manual-test","cwd":"/path/to/project","terminationReason":"NO_TOOL_CALL","fullyIdle":true,"lastUserInput":"manual hook test","error":""}' | agent-handoff hook agy
```

It must print `{}` and exit 0. If a report is created for a real conversation, the hook is working.

Notes:

- AGY writes hooks to `~/.gemini/config/hooks.json`.
- A `Stop` with `fullyIdle: false` is recorded as `blocked`.
- A conversation outside a mapped project does not create an automatic report.

## Duplicate reports

Possible causes:

- The same session idle event fired twice with a different fingerprint.
- A manual `complete` was run in addition to automatic capture.
- The session mapping file was deleted.

Check `AUTO.json` inside the task directory and `state/sessions.json`. Automatic capture deduplicates by event key. Do not delete duplicate evidence blindly; mark it superseded or leave it for audit.

## Disk is nearly full

Reports are small, but queue retries and logs can grow. Archive old local task data only after verifying it is uploaded and backed up. Do not delete the only copy of a pending report.

## Permissions

Expected:

```bash
chmod 700 "$AGENT_HANDOFF_HOME"
chmod 600 "$AGENT_HANDOFF_HOME/config/config.json"
chmod 600 "$AGENT_HANDOFF_HOME"/logs/*.log
chmod 600 ~/.config/rclone/rclone.conf
```

## Re-run tests

```bash
PYTHONPATH=lib python3 -m unittest discover -s tests -p "test_*.py" -v
python3 tests/acceptance.py
```

The acceptance suite uses an isolated `/tmp/agent-handoff-acceptance` home and a fake rclone remote for synthetic checks. Its live checks read the configured Drive hierarchy and do not create or delete Drive folders.

## Dispatcher is disabled

`agent-handoff dispatch run` refuses to start when `dispatch.enabled` is false. Core capture still works. Add the `dispatch` section to the runtime config; do not replace the whole config with an example.

```bash
agent-handoff config validate
```

## Dispatcher refuses the configuration

Common causes:

- `dispatch.repository` is not `owner/name`.
- The repository is public; v1.1 requires a private repository with Issues enabled.
- The authenticated `gh` user is not in `dispatch.allowed_users`.
- A dispatch project is not present in the core `projects` mapping.
- A dispatch workspace does not exactly match one of that project's recorded paths.
- A model alias is missing from `dispatch.models`.
- `workspace_write` was selected without `allow_write: true`, or `allow_write` was enabled with `read_only`.

Fix the config and rerun:

```bash
agent-handoff config validate --json
agent-handoff doctor
```

## Issue request was rejected

The dispatcher rejects, without executing:

- missing or unsupported `handoff-version`;
- unknown or duplicate metadata fields;
- unknown project, agent, or model alias;
- `session: same` (SAME SESSION is deferred, never simulated);
- empty or oversized instructions;
- unauthorized authors.

A rejection comment is marker-idempotent. Editing a rejected issue does not automatically execute it; submit a new corrected issue.

## Dispatch record is NEEDS_ATTENTION

This means a process restarted after a claim/start and no recoverable session output was found. The agent is **not** rerun automatically.

Inspect without changing anything:

```bash
agent-handoff dispatch status --json
agent-handoff dispatch inspect --task <task-id> --run <run-id> --json
```

If the work must be repeated, submit a new issue. Do not edit the ledger to force a rerun.

## A dispatcher run was interrupted

An interrupt during a slow upload is safe. The durable record keeps the existing OpenCode session, task, and run identity; it normally remains `UPLOAD_PENDING` with capture complete. Do not submit a duplicate issue and do not delete the task directory. A later poll retries only the upload and publication:

```bash
agent-handoff dispatch status
agent-handoff dispatch run --once --progress
```

If the status says `stalled` because the dispatcher process is gone, the same command reconciles persisted session output without re-executing OpenCode. Use `--json` for scripts; progress is written to stderr.

## Upload is pending but the report is readable on Drive

A readable file is not upload verification. Check:

```bash
agent-handoff dispatch status --json
agent-handoff dispatch inspect --task <task-id> --run <run-id> --json
```

`dispatch status` reports `health=retryable`, `phase=retry_upload`, the next retry time, and whether only the upload will run. If local verification is missing, retry the upload only:

```bash
agent-handoff retry-upload --force --task <task-id> --run <run-id>
```

If local verification succeeded but the remote `COMPLETE.json` still says pending, reconcile and publish without rerunning the agent:

```bash
agent-handoff dispatch deliver --task <task-id> --run <run-id> \
  --issue <number> --repository owner/private-dispatch
```

This creates and verifies `UPLOAD-RECEIPT.json`, re-uploads truthful verified `COMPLETE.json`, and publishes the direct URL idempotently.

## GitHub publication failed

The report is safe; only the comment failed. The record remains `UPLOAD_VERIFIED` and retries automatically with backoff. `dispatch status` reports `health=retryable`, `phase=retry_publication`, the verified report link, and the next retry. Force a retry with:

```bash
agent-handoff dispatch run --once --force --json
```

Only the comment is retried; the verified upload is reused.

If `dispatch status` reports `health=attention` with `phase=publication_exhausted`, `dispatch.delivery.max_attempts` was reached. The verified upload is still intact. Publish manually without re-running the agent:

```bash
agent-handoff dispatch deliver --task <task-id> --run <run-id> --issue <number> --repository owner/private-dispatch --json
```

Before posting, the dispatcher checks for the delivery marker. A retry after an uncertain comment post does not create a duplicate link.

## Dispatcher status is ISSUE_UPDATED but I cannot see the comment

Confirm the record's `comment_url` and open the issue in the authenticated browser session. Private repository visibility is required. A comment URL is publication evidence, not upload verification.

## Tests and live checks

```bash
PYTHONPATH=lib python3 -m unittest discover -s tests -p "test_*.py" -v
```

Deterministic tests do not need Drive or provider credentials. Live dispatch testing requires real `gh`, OpenCode provider auth, and Drive auth; if any are unavailable, report the limitation instead of claiming a pass.
